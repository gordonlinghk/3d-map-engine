1項目是什麼

一個程序生成 3D 城市地圖引擎(Web / Three.js / TypeScript),定位是「3D city atlas / interactive map engine」,並自 C1 起附帶一個可在其上建遊戲的邏輯層。它以 pnpm monorepo 組織成七個可獨立消費的 SDK package 加一個 demo 應用:

Package一句話依賴
@map-engine/core資料模型 + 確定性程序生成 + 序列化零依賴(無 DOM / Three / React)
@map-engine/terrain真實高程:terrarium DEM 磁磚(AWS)→ chunk 高度網格core
@map-engine/historical人工考據歷史地圖包(三國中國),帶出處/confidence;6 個年份 era 快照(C3/C4)core
@map-engine/osmOpenStreetMap 真實城市匯入(Overpass → MapWorld)core
@map-engine/game遊戲邏輯:道路圖 A\* 尋路、確定性單位移動、事件模擬core(零 DOM / Three)
@map-engine/threeThree.js 渲染 adapter:mesh、相機、picking、環境、模擬、編輯器、單位視圖 + 鏡頭跟隨core、game;peer three>=0.170
@map-engine/uiReact demo UI:搜尋、列表、面板、工具列、迷你地圖core、zustand、fuse.js;peer react>=18
@map-engine/demoVite app,把一切組起來(private,不發佈)全部 + @anthropic-ai/sdk

功能全景:三種程序生成 preset、Orbit/Fly/Walk 相機(Walk 含碰撞)、點選/搜尋/資訊面板、日/黃昏/夜三種環境(真陰影、夜間發光窗、街燈、星空)、車流渡輪飛機模擬、自然語言生成地圖(Claude API + 本地解析)、真實城市匯入(OSM + 真實高程)、三國歷史地圖(中式建築風格、勢力著色、年份切換)、POI 註記、完整建築編輯器(undo/redo + 持久化),以及 C1 遊戲邏輯層(A\* 尋路 + 單位模擬 + 鏡頭跟隨,demo 內 ?game=1 試玩)。

六條不可違反的硬性規則
  1. @map-engine/core 永遠不 import Three.js、React 或任何 DOM API。
  2. 所有程序生成必須確定性:同 seed + config → byte 級相同的世界。生成路徑禁用 Math.random() / Date.now(),一律走 createRng()。
  3. 渲染 mesh 不進核心資料模型;MapWorld 只有資料。
  4. 所有可互動物件必須有穩定 id 與 metadata。
  5. 每個開發階段結束時必須有可運行 demo + 通過的測試。
  6. Demo 使用真實公司公開文字資料(無 logo 圖像)——已獲項目擁有者授權。

2快速開始

2.1 環境需求

Node ≥ 20(開發時為 24.13)、pnpm 11(packageManager 已釘 pnpm@11.0.8)。首次跑 e2e 前需 npx playwright install chromium。

2.2 常用命令

pnpm install            # 安裝(注意:pnpm-workspace.yaml 已允許 esbuild build script)
pnpm dev                # demo dev server → http://localhost:5173
pnpm test               # 47 個單元測試(Vitest)
pnpm test:e2e           # Playwright 全部(desktop / large / mobile 三種 viewport)
npx playwright test --project=desktop     # 只跑 desktop(日常最常用,~1.5 分鐘)
pnpm lint && pnpm typecheck                # ESLint + tsc project references
pnpm build              # demo 生產建置(Pages 用 DEPLOY_BASE=/3d-map-engine/)
pnpm build:lib          # tsup 建置四個 SDK package(dist/:ESM + d.ts)
pnpm release            # 發佈到 npm(目前刻意擱置,見 §12.2)

3核心概念與詞彙表

術語定義定義處
MapWorld一張地圖的完整純資料:config、chunks(高度網格)、objects(建築/地標/樹)、districts、blocks、roadGraph、landmarks、可選 water/greenPolygons。可整體 JSON 序列化。core/types.ts
seed / determinism任何生成輸入僅為 (seed, config)。RNG 為 mulberry32;rng.fork(label) 派生的子流只取決於 (seed, label),與消費順序無關——這是 chunk 順序無關性的機制。core/rng.ts
chunk200×200 世界單位的地形塊,33×33 高度取樣(CHUNK_RESOLUTION=32)。chunk 同時登記落在其中的 object id。core/world.ts
preset三種出廠地圖形態:coastal-tech-city(西南大陸+東北海灣+跨灣橋,SF 風)、island-city、downtown-night-grid。core/presets.ts
MapDirectivesPrompt-to-map 的中間層:LLM 或本地解析只輸出這組受控欄位(preset/環境/hilliness/密度/樓高…),applyDirectives() 負責 clamp 成合法 MapConfig。LLM 永遠碰不到原始 config。core/directives.ts
EditOverlay編輯器的持久化格式(v2):建築 {modified[], added[], deleted[]} + POI {addedPois[], modifiedPois[], deletedPois[]},只存差異;normalizeOverlay() 把舊 v1 資料(localStorage/草稿)無損遷移到 v2;重生成同一世界後以 applyEditOverlay() 重放。core/edits.ts
layer渲染圖層 id(封閉 union MapLayerId):terrain / water / roads / buildings / trees / landmarks / labels / traffic。UI 圖層面板逐一開關。core/types.ts
quality渲染品質開關:'high'(預設,含陰影)/'low'(無陰影、pixelRatio 1)。自動化環境(navigator.webdriver)預設 low;URL ?q= 可強制。three/renderer.ts
世界座標慣例原點在地圖中心;北 = −Z;Vec2.y 在 footprint/boundary 語境代表世界 Z。全域慣例

4架構總覽

三個關鍵解耦:

  • 資料與渲染分離:任何來源(程序生成 / prompt / OSM / 未來新來源)只要產出 MapWorld,渲染、互動、模擬、編輯全部自動可用。
  • UI 與 renderer 解耦:UI 只依賴 MapRendererLike / BuildingEditorLike(ui/src/types.ts 的結構型介面),TypeScript structural typing 讓 ThreeMapRenderer 自動滿足——UI package 完全不 import Three.js。
  • 編輯與生成分離:編輯以 overlay 差異存放,世界本體永遠可以由 seed 重生成。

5@map-engine/core 深入

檔案職責與關鍵匯出
types.ts整個系統的詞彙表。MapWorld、MapConfig、BuildingInfo(含 footprint: Vec2[]、source: 'procedural'|'imported'|'user-defined')、RoadGraph、CityBlock、MapLayerId、chunkKey()。改任何型別前先看 §13.6 牽動表。
rng.tscreateRng(seed):mulberry32 + xmur3 字串雜湊。介面:next/int/float/pick/chance/fork。fork(label) = createRng(seed + '/' + label),順序無關。
noise.tscreateNoise2D(seed):2D value noise + fBm。純函數 of (seed, x, y),無內部狀態。
terrain.tscreateHeightSampler(seed, config) → (x,z)=>height(公尺,負值在水下)。共用 fBm 場 + per-preset 大尺度遮罩:coastal 用對角線大陸遮罩 + 海灣高斯挖除 + 兩個島嶼凸起;island 徑向衰減;downtown 平台。歸一化場的海平面常數 SEA=0.34。
roads.tsgenerateRoadGraph():市中心街道格網(每 4 條為 avenue)+ 兩條貫穿高速 + per-preset 跨水線;採樣線段,水上段自動標記 kind:'bridge',岸外多餘段裁掉。cityGridExtent(config) 是街區與道路共用的範圍函數——兩邊必須同源。
city.tsgenerateCity():街區分類(downtown<170m、commercial<400m、waterfront 近水、park 隨機+固定帶)→ 每街區分 2×2 或 3×3 lot 按密度擲骰生成建築 → 樓高按類型與離心距衰減 → 28 家真實公司分配到最高辦公樓(Salesforce 強制最高)→ 地標(橋/Alcatraz/Sutro/Coit/球場/渡輪大樓)由地形特徵解析位置 → 公園與山坡散佈樹木。
companies.tsCOMPANIES:28 家 SF 公司的公開資料(創辦人/估值/產品/HQ),文字 only。
world.tsgenerateWorld(seed, config) 總裝配;generateChunk(world, coord) 順序無關重生成;createWorldHeightSampler(world)——從 chunk 高度網格雙線性取樣(不重算地形函數),詳見 §10.2。
directives.tsPrompt-to-map 資料層:MapDirectives、applyDirectives()(clamp 至安全範圍)、parsePromptLocally()(中英關鍵詞離線解析)、MAP_DIRECTIVES_JSON_SCHEMA(給 LLM 的結構化輸出 schema)。
edits.ts編輯持久層:EditOverlay、applyEditOverlay()、chunk 一致性維護的 add/remove/replaceBuildingInWorld()、幾何工具 moveFootprint()/rotateFootprint()。
serialize.tsserializeMap/deserializeMap:版本常數檢查 + structuredClone 快照隔離。JSON-safe。
presets.ts三個 MapConfig preset;getPresetConfig() 回傳深拷貝。
改 core 的安全網determinism 測試(同 seed 深比較、chunk 順序無關、序列化 roundtrip)是最敏感的警報器。動 core 之後第一件事永遠是 pnpm test。

6@map-engine/three 深入

6.1 renderer.ts —— 一切的組裝點

createThreeMapRenderer({container, quality}) 回傳 ThreeMapRenderer。內部生命週期:

  1. 建 WebGLRenderer(preserveDrawingBuffer:true 供截圖;quality 決定 shadowMap 與 pixelRatio)、Scene、相機、Hemisphere + Directional 光(太陽投影,PCFSoft 2048,shadow camera 在 loadWorld 時按地圖半徑配置)。
  2. loadWorld(world):清除舊 worldRoot(遞迴 dispose geometry/material/texture)→ 依序構建各圖層 group(見下表)→ 建 pickables 索引與高亮物件 → rig.setTerrain/setColliders → 重套環境 → home 視角 → 發 world:loaded。
  3. frame loop:rig.update(dt) → 節流 hover picking(90ms,pointer lock 時跳過)→ 高亮脈動 → simulation.update → 水面/警示燈 tick → 使用者 onFrame 回呼 → render。
圖層 id構建函數內容
terrainbuildTerrainGroup(+buildFlatAreas)每 chunk 一個高度網格 mesh,頂點色 = 街區 kind(BLOCK_COLORS)或高度帶;OSM 的水/綠多邊形平面也掛在此;勢力染色(C3)——海平面以上頂點若落在有 color 的 district 內,顏色朝該色 lerp 0.45(§10.6)
waterbuildWaterMesh大海平面 + 程序 ripple normal map(userData.tick 漂移 offset)
roadsbuildRoadsMesh全部道路合併為單一 quad-strip geometry,沿 sampler 高度 +0.35;橋面恆定 waterLevel+7,紅色
buildingsbuildBuildingsGroup多路徑:軸對齊矩形 → 4 個高度等級 InstancedMesh(窗戶 CanvasTexture);任意多邊形 → 單一合併 ExtrudeGeometry + userData.faceRanges;style:'chinese' → 多邊形 body + 合併歇山屋頂(亦帶 faceRanges)(§10.3)。另含屋頂退台/天線 instanced。setNightMode() 切換夜間 emissive 貼圖
treesbuildTreesGroup樹幹+樹冠兩個 InstancedMesh
landmarksbuildLandmarksGroup手工低模(吊橋=塔+三段 QuadraticBezier 纜索、電視塔、球場、碼頭、監獄島);userData.setNight/tick 控制夜光與警示燈閃爍
trafficcreateSimulationLayer車(instanced,沿 road graph polyline,路口隨機續行)、渡輪(pier↔island 折返+浮沉)、飛機;update(dt) 由 renderer loop 驅動
(scene 級)buildStars / streetLights星空(夜間 visible)、街燈(夜間 emissive)

6.2 其他模組

檔案重點
cameraRig.ts三模式:orbit(OrbitControls damped)、fly(左鍵 drag-look + WASD/QE/Shift,滾輪調速,禁止入地)、walk(pointer lock、貼地 eye 2.3m、碰撞、海面阻擋、head bob)。focusOn() 回 Promise 的 easing tween,結束後落回 orbit。切到 fly/walk 時才從 camera quaternion 同步 yaw/pitch(程式化設定朝向要「先 lookAt 再 setMode」)。鏡頭跟隨(C1):setFollowTarget(get) 每幀輪詢一個點、保持起始取景平滑追蹤;update 分支序 tween > follow > orbit/free;跟隨會關 orbit.enabled,故 setMode/goHome/focusOn 取消跟隨都經 stopFollow() 還原輸入(否則相機鎖死——終審抓到的坑)。
gameView.tscreateGameView(renderer, sim):@map-engine/game 的 Three 綁定。每單位一 marker(預設朝 +Z 的錐體,heading→rotation.y)、訂閱 unit:spawned/removed 建/棄 mesh、每幀 onFrame 內 tick sim 再同步 transform、followUnit(id|null) 接鏡頭跟隨、dispose() 全清。純邏輯(A*/單位/事件)留在 game 包可 node 單測,渲染綁定在此。
interaction.tsbuildPickableIndex(footprint 全點 AABB → 半徑/尺寸);createPicker(instanced instanceId 映射 + 多邊形 mesh faceIndex 二分查找 + 地面 raycast);createHighlights(hover 環+邊框、selected 脈動雙環,additive blending)。
collision.ts純 TS(可 node 單測):建築 footprint + 實體地標的 2D AABB 進 48 單位 cell 空間雜湊;resolveMovement() 逐軸解算 = 天然沿牆滑行;橋與公園不阻擋。
editor.tscreateBuildingEditor(renderer, world, {initialOverlay, onOverlayChange}):命令堆疊(100 步,apply/revert 成對)、拖曳移動(半透明 ghost 預覽,依賴 pickGround + setEditorDragging)、樓高/改名/旋轉±15°/刪除/點地新增、overlay 追蹤。每次 commit 後呼叫 renderer.refreshBuildings()。
tour.ts地標 + 前六高公司樓輪播 focus,3.2s 停留。
events.ts型別化 emitter。事件:object:hover / object:selected / object:cleared / camera:changed / world:loaded。

6.4 @map-engine/game 遊戲邏輯層(C1)

純、確定性、零依賴(只依賴 core,無 DOM/Three)——把 MapWorld 變成可在其上建遊戲的基底。渲染綁定(gameView.ts)與鏡頭跟隨在 @map-engine/three,見 §6.1–6.2。

模組重點
pathfinding.tsA\* 尋路。buildGraphIndex(roadGraph)(建一次、重用):道路圖視為無向、邊 cost = 幾何 XZ 長度 → 直線 Euclidean 啟發式 admissible/consistent → findPath 回最短路。二元最小堆積,tie-break(f→g→node id)確定性。nearestNode(index,x,z) 把世界座標吸附到最近道路節點;findPathBetweenPoints 兩端各吸附。回傳 {found, nodes[], points[], cost}。
simulation.tscreateGameSimulation(world, opts?):spawnUnit/moveUnitTo(id, {x,y})(Vec2:.x=世界x、.y=世界z)/setUnitPath/stopUnit/removeUnit/getUnit/listUnits/on/tick(dt)。tick 沿路徑弧長推進單位、createWorldHeightSampler 貼地、更新 heading、發事件 unit:spawned/waypoint/arrived/removed。flush 有重入保護保證嚴格發射順序(handler 內生/棄單位安全)。給定 (world, spawns, dt 序列) 完全確定性。
慣例與坑Unit.position、getUnit/listUnits 回傳的是活引用(sim 每 tick 就地改),外部只讀勿改。事件多在 tick 發,但 spawnUnit/removeUnit/零距離 moveUnitTo 會同步發(所以消費端要同時從 listUnits() 種子化,如 createGameView)。單位速度須 > 0 才會移動。demo ?game=1 把單位生在同一連通分量以保證互可達。

8@map-engine/osm 深入

流程:fetchOsmArea(bbox)(Overpass POST,抓 building/highway/water/park)→ osmToWorld(data, {name, bbox}) 純轉換:

  • 投影:等距圓柱近似,以 bbox 中心為原點,x=(lon−lon0)·111320·cos(lat0)、z=−(lat−lat0)·111320(北=−Z)。
  • 建築:閉合 way → footprint 多邊形(<12㎡ 過濾);高度 = height tag → building:levels×3.2 → id 雜湊 fallback;類型映射(office→company、apartments→residential…);命名建築進搜尋(tags 加 'Named');id = bldg:osm:{wayId}。
  • 道路:highway 分級映射(motorway→highway、primary→avenue、residential→street,footway/steps 略過);共享 OSM node id = 路口自然連通,車流直接可跑。
  • 水/綠地:閉合多邊形進 waterPolygons/greenPolygons(由 three/flatAreas.ts 渲染平面);公園內point-in-polygon 散佈樹木。
  • chunk:平地(OSM_GROUND=2)高度網格覆蓋 bbox。

城市預設(cities.ts):hong-kong-central(1,815 棟)、tokyo-shibuya(2,574 棟)、manhattan-midtown、london-city。

城市搜尋(geocode.ts):GeocodingProvider 介面(searchCities(query, {limit, signal}) → CityCandidate[]:name/region/country/lat/lon/bbox/label/place id)。預設 createPhotonProvider()——Photon(komoot)免 key、OSM 生態、官方支持 autocomplete(Nominatim 使用政策禁止 as-you-type,故不用);createMockGeocodingProvider() 供離線/測試;可注入 fetchFn 做單元測試。錯誤已轉成用戶友好訊息(429 → rate-limited、網絡失敗 → unreachable),AbortError 原樣拋出供取消邏輯識別。candidateToCityArea(candidate, {scale}) 把候選裁剪成 bbox 視窗——UI 的 AREA 選單提供 1×(~1.3×1.8km)/2×/3× 倍數(clamp 1..3;整個城市的 extent 會令 Overpass 與渲染器爆炸;provider extent 比視窗小則照用),產出 {slug:'bbox:s,w,n,e', name, bbox};parseBBoxSlug() 反解析並校驗(拒絕反轉/越界/每邊 >6.5km)。>1× 的載入走 fetchOsmAreaTiled(tileKm 2,loading 畫面顯示磁磚進度),並以 boot 的 AbortController 貫穿取消——否則 StrictMode double-mount 的第一個 boot 會在背景繼續抓磁磚。UI 端(ui/CitySearch.tsx)負責 debounce 400ms、≥2 字元、AbortController 取消、序號防過時覆蓋、per-query cache、鍵盤導航;選中後 demo 導航 ?bbox=…&cityName=…,復用既有 Overpass→osmToWorld 流程。要接 Mapbox/Google:實作同一介面,key 走 Vite env(import.meta.env.VITE_*),不進 repo。

大範圍烘焙(bake.ts + scripts/bake-city.ts):live 抓取限 ~1.3×1.8km 視窗;更大範圍用 pnpm bake --city "Hong Kong" --size 3 離線烘焙——splitBBox 切成 ≤1.2km 磁磚 → fetchOsmAreaTiled 順序抓取(磁磚間 1.5s 延遲、失敗 5/15/45s backoff 重試 3 次)→ mergeOsmResponses 按 type+id 去重(跨磁磚邊界的 way 會重複出現)→ 一次 osmToWorld → serializeMap 寫檔。demo 用 ?world=<url> 載入;遊戲直接 deserializeMap()。>8km 需 --force(公共 Overpass 禮儀 + 單 mesh 渲染上限)。實測 3×3km 香港:9 磁磚 205s、3,153 棟、7.2MB、瀏覽器 boot ~1s。注意:Node fetch 預設無 User-Agent,Overpass 會回 406——fetchOsmArea 已固定送出識別 UA(瀏覽器忽略該 header)。

真實高程(@map-engine/terrain,A5):terrarium DEM 磁磚(Mapzen/Tilezen @ AWS Open Data,免費免 key,h=R·256+G+B/256−32768)→ fetchElevationGrid(bbox)(Web-Mercator tile 數學、zoom 按磁磚預算自選 ≤14、瀏覽器 canvas 解碼 / Node 注入 pngjs)→ applyTerrainToWorld(world, sample, {bbox}):① chunk 高度 = groundOffset + (elev − 最低陸地elev),海(elev ≤ 0.05m)= −1.6 → 低於 waterLevel,海岸/維港自動出現;② 水體多邊形下地形壓平成湖床;③ 建築沉到 footprint 最低點、道路節點/樹重新取樣(roadMesh/simulation/streetLights 本來就自己取樣,自動跟隨);④ 署名寫入 world.attribution(SidePanel footer 渲染,授權義務)。demo 預設開啟(?flat=1 退出、失敗退平地),bake CLI 同(--flat)。實測香港中環:−1.6 至 479.8m。

OSM 剩餘限制(= OSM v2 待辦)① 平地無高程(A5 已修)② 不處理 multipolygon relations(少數大型複雜建築缺失)③ 海岸線海面未重建(A5 已大致修復——海面來自 DEM 的海平面,非 OSM coastline;個別內灣仍可能不準)。

10五大關鍵機制詳解

10.1 Determinism 的實作鏈

字串 seed → xmur3 → mulberry32 主流;每個子系統用 fork('terrain')、fork('chunk/3,-2')、fork('bldg/{i},{j}') 取獨立流。因為 fork 只依賴 label,任何 chunk / 街區可以按任何順序重生成而結果不變。噪聲是 (seed,x,y) 純函數。測試以「整個 MapWorld 深比較」鎖死此性質。

10.2 高度取樣:chunk 是唯一真相

createWorldHeightSampler(world) 對 chunk 高度網格雙線性插值,超出範圍才 fallback 地形函數。這讓道路、車流、街燈、Walk 貼地、地標朝向與渲染出來的地形 mesh 完全一致,而且 OSM 等「非程序生成」世界自動正確。推論:想改地形高度,改 chunk heights,別想著只改 sampler。

10.3 建築渲染與 picking 的多路徑

軸對齊矩形(程序生成)

  • 4 個高度等級,各一個 InstancedMesh
  • 窗戶 = 等級化 CanvasTexture(日/夜兩套,夜間作 emissiveMap)
  • picking:raycast → instanceId → id 陣列

任意多邊形(OSM / 編輯器旋轉後)

  • 全部 ExtrudeGeometry 合併成單一 mesh(單 draw call)
  • 頂點色上色;夜間統一柔和 emissive
  • picking:raycast → faceIndex → userData.faceRanges 二分查找

分流判斷 isAxisAlignedRect(footprint) 在 buildingsMesh.ts。編輯器旋轉建築後 footprint 不再軸對齊,自動改走右邊路徑——這是兩個功能共用一條管線的例子。

第三條路徑:中式建築(C2)BuildingInfo.style === 'chinese'(可選欄位,預設 modern)的建築改走多邊形 body 路徑(暖牆、無玻璃窗、經 faceRanges 可 pick),並疊加一個合併的**歇山/廡殿式屋頂 mesh**(makeHipRoof:base 依 footprint w/d、脊沿長軸、方形退化為攢尖、簷口外挑;瓦色青灰、牆色木紅/夯土;長條城牆按長寬比 gate 不加頂)。三國城池主殿+城牆用此風格。屋頂 mesh 亦帶 faceRanges(id=主殿 id),picker 的 resolveMerged() 同時解析 body 與 roof——否則點屋頂(高於且外挑於牆身)會 miss 而取消選取(終審抓到的回退)。任何世界皆可用此欄位。

10.4 編輯器:命令 + overlay 雙層

命令層(session 內):每個操作是 {apply, revert},進 100 步歷史;commit / undo / redo 後一律 refreshBuildings()(重建 buildings group + pickables + colliders,並重掛選取高亮)。overlay 層(跨 session):editor 追蹤 modified/added/deleted id 集,任何變化即時導出 EditOverlay 交給 demo 存 localStorage;下次載入同一世界時先重放。匯出 JSON = serializeMap(world) 全量下載,可作遊戲存檔格式。

草稿檔層(跨機器 / 跨裝置):core/draft.ts 定義 .mapdraft.json 格式 —— {format, version, name, createdAt, updatedAt, base, overlay}。base 分兩種:程序生成世界只存配方({kind:'procedural', seed, directives},幾 KB);OSM 世界內嵌完整 serializeMap 快照({kind:'imported', sourceSlug, snapshot}),因為 Overpass 資料會漂移。開檔流程(demo/drafts.ts + App.tsx):parseDraft() 校驗 → 草稿存入 sessionStorage(綁定目標 URL)→ 整頁導航 → boot 偵測 pending draft 優先於 URL 生成路徑 → sanitizeOverlayForWorld() 剔除引用已消失建築的條目(漂移防護)→ 套用 overlay → 自動進入編輯模式。存檔:支援 File System Access(Chromium)時經 file handle 覆寫同一檔案,否則下載;navigator.webdriver 一律走下載路徑(headless 無法操作原生對話框)。注意 sessionStorage 的 pending draft 是「保留不消費」的——React StrictMode 會 double-mount,若第一次 boot 就刪掉,第二次 boot 會退回 URL 路徑;改為 URL 不匹配時才清除,順帶讓「開草稿後手動刷新」保持狀態。

10.5 quality 機制與 CI 的關係

Shadow pass 讓 CI 的軟件渲染主線程完全飽和 → UI 互動超時。因此 navigator.webdriver 環境預設 quality:'low'(無陰影、pixelRatio 1),真人瀏覽器一律 high;?q=high|low 強制。headless 截圖要看陰影必須帶 ?q=high;headless 顯示的 FPS(4~8)是軟渲染假象,不代表真機效能。這個開關同時是未來低端裝置降級的現成入口。

10.6 勢力著色與歷史年份快照(C3/C4)

勢力著色是純資料驅動:core/types.ts 的 District 加了可選 color?: string(不設色 = 零影響,procedural/OSM 世界從不填它)。three/terrainMesh.ts 為每個 chunk 建頂點色時,對海平面以上的頂點額外查一次:它落在哪個有色 district 的多邊形內,就把頂點色朝該 district 的顏色 lerp 0.45。多個有色 district 邊界重疊時(例如一座小城的勢力範圍被畫在大勢力的整體邊界裡),候選 district 先按面積由小到大排序再逐一 point-in-polygon 測試,第一個命中就採用——這保證了「飛地」(enclave)贏得染色,而不會被外層大勢力覆蓋。

年份切換是有限的手工 era 快照,不是逐年規則模擬:historical/types.ts 新增 HistoricalEra({id, year, name, factions, ownership, kindOverrides?, nameOverrides?, sources}),HistoricalMapData 加 eras? + defaultEra?。historicalToWorld(data, {era}):不傳 era、傳的等於 defaultEra、或傳一個查無此 id 的字串(例如來自 URL 的髒資料),一律回退基準快照(world.id = 'hist:three-kingdoms');傳一個合法 era id,則按該 era 的 ownership(cityId → factionId,'neutral' 合法,代表當年無主)重新決定每座城的所屬勢力 district,kindOverrides/nameOverrides 視需要換城池型態或改名(如許昌在 200 年是漢獻帝所在),world.id = 'hist:three-kingdoms:<eraId>'。三國資料包目前有 6 個 era,依年份排列:y194 群雄並起(14 勢力,C4 新增——漢末最分裂的一幕,取興平元年年中之勢)、y200 官渡之戰(9 勢力)、y208 赤壁前夕(8 勢力)、y219 襄樊之戰後(4 勢力)、y229 三國鼎立(= 基準資料,預設 era)、y264 蜀漢既亡(2 勢力,C4 新增——蜀漢亡後、晉代魏前的二分之勢,曹魏盡吞益州)。每個 era 的 ownership 是原始整理自正史的編纂,並非任何第三方資料集的複製,每筆皆帶 sources。

Demo 端:?era= URL 參數;Toolbar 新增 📅 ERA <select>(data-testid="era-select"),只在載入的地圖有 eras 時出現;選擇預設 era 會清空 ?era 參數;草稿的 sourceSlug 內嵌 era(如 hist:three-kingdoms:y200),重新開啟該草稿會還原到對應 era。

設計取捨era 是完整快照而非內插值——好處是每筆 ownership 都可審查、可標出處;代價是兩個 era 之間的年份無法顯示,新增一個年份 = 新增一整筆完整覆蓋所有城市的 HistoricalEra 資料,而不是改一兩個欄位。

14陷阱清單(全部實戰踩過)

#症狀原因與修法
1某 mesh 資料正常但完全看不到三角形繞向反了 → backface culling 整批剔除(Phase 3 的道路)。檢查 winding 或暫時 DoubleSide 定位。
2CI e2e 大面積超時、本地全綠CI 軟渲染 + shadow pass 卡死主線程 → quality 機制(§10.5);另有 retries 2 + 120s。
3e2e 裡程式化設好朝向後相機亂走headless pointer lock 行為不一,合成 pointermove 用舊 yaw/pitch 覆蓋。先 camera.lookAt 再 setCameraMode('walk');測試避免點 canvas(觸發 pointer lock)。
4tsup --dts 報 TS6307與 composite tsconfig 衝突 → 獨立 tsconfig.build.json。
5Pages deploy「try again later」/ 重跑更糟暫時性;重跑用 gh workflow run 開新 run,勿 rerun --failed(artifact 重名)。
6Playwright strict mode:2 個 canvas迷你地圖也是 canvas → locator('canvas').first()。
7右側面板按鈕點不到 / 被蓋住工具列 .shifted 邏輯:selectedId 或 editMode 時 right:328 + top:64。新增右側面板記得同規則。
8headless FPS 只有 4–8,以為效能爆炸軟渲染假象。真機基準由操作者確認流暢(含陰影)。
9深海角落地形測試「不同 seed 應不同」失敗海底深度被 clamp 成常數——比較中央 chunk。
10mobile e2e 找不到側欄內容mobile 預設收起 → 先點 side-open。
